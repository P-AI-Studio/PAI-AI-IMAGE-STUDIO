# P.AI AI IMAGE STUDIO

**نسخه:** `1.0.0-beta.2` · **سیستم‌عامل:** ویندوز ۱۰/۱۱ نسخهٔ ۶۴ بیتی · **وضعیت:** نسخهٔ آزمایشی عمومی

P.AI AI IMAGE STUDIO یک برنامهٔ مستقل دسکتاپ برای تولید تصویر، ویرایش دستوری، بازسازی و افزایش وضوح، Close-up / Smart Zoom، گسترش تصویر به قاب مربع و بزرگ‌نمایی عصبی است. رابط، مدیریت Workflowها، کاتالوگ مدل، تنظیمات، بوم پیش‌نمایش و فضای کاری محلی متعلق به همین برنامه است. برای اجرای محلی از موتورهای inference و مدل‌های شخص ثالث استفاده می‌شود که منبع و مجوزشان در ادامه و فایل `licenses/THIRD_PARTY_NOTICES.txt` درج شده است؛ اجرای برنامه به رابط گرافیکی دیگری نیاز ندارد.

> **مجوز مهم:** مجوز فعلی مخزن، مشاهده و ارزیابی را مجاز می‌داند و اجازهٔ عمومی برای استفاده، تغییر یا توزیع مجدد صادر نمی‌کند. عمومی‌بودن مخزن GitHub به‌تنهایی به‌معنای متن‌باز بودن یا اعطای مجوز نیست. پیش از استفاده یا توزیع، `LICENSE` را بخوانید. مجوز Runtimeها و وزن‌های مدل نیز جداگانه است.

## ویژگی‌های اصلی

- **اجرای محلی:** پس از نصب Runtime و مدل‌ها، inference تصویر روی سیستم انجام می‌شود و مسیر پیش‌فرضی برای ارسال تصویر به API میزبانی‌شده وجود ندارد. برای دانلود Runtime، مدل یا به‌روزرسانی انتخاب‌شده، اتصال شبکه لازم است.
- **شش Workflow/ابزار:** Image Generate، Image Edit، Enhance / Upscale، Close-up / Smart Zoom، Square 1:1 و قابلیت Ultimate با بزرگ‌نمایی مستقل مدل‌محور.
- **Qwen Image 2.1 Turbo:** مسیر Turbo در صورت سازگاری مدل و Runtime از برنامهٔ ثابت هشت‌گامی و تنظیمات Euler/CFG مورد انتظار استفاده می‌کند. Checkpointهای دیگر ممکن است تنظیمات متفاوتی بخواهند.
- **یکپارچه‌سازی Ultimate و Real-ESRGAN:** فقط یک دکمهٔ Ultimate وجود دارد. مدل از مسیر **Model Catalog → Ultimate** انتخاب می‌شود؛ مسیر آن شامل بازسازی اولیهٔ Qwen، بزرگ‌نمایی با مدل یادگرفته‌شدهٔ انتخابی و سپس اصلاح دیتیل با Tileهای هم‌پوشان Qwen است. Lanczos دیگر روش اصلی افزایش وضوح در این مسیر نیست.
- **پروفایل‌های دیتیل:** Balanced حفظ وفاداری به تصویر منبع را اولویت می‌دهد؛ Strong بازسازی قوی‌تری انجام می‌دهد؛ Maximum آزمایشی است و ممکن است هویت، هندسه یا جزییات صحنه را تغییر دهد.
- **حالت‌های قابل انتخاب Preview:** Original، Enhanced، Slider، Side by side، Overlay، Difference و Flicker برای Workflowهای دارای تصویر ورودی. Image Generate فقط پیش‌نمایش Live دارد.
- **Close-up محلی:** مدل متنی/تصویری سازگار می‌تواند در یافتن سوژه کمک کند؛ انتخاب دستی نقطهٔ فوکوس نیز موجود است. تشخیص معنایی تضمین‌شده نیست و موارد مبهم باید بازبینی شوند.
- **فضای کاری محلی:** تنظیمات، مدل‌ها، Runtime، Cache و خروجی‌ها در فضای `data/` کنار برنامه سازمان‌دهی می‌شوند.
- **اعتبارسنجی ورودی‌ها و دانلود:** هدر و ابعاد تصاویر، هدر فایل مدل، مسیرهای آرشیو، نشانی‌های loopback، HTTPS و هش‌های معتبر منتشرشده در صورت وجود بررسی می‌شوند. برای مدل‌هایی که ناشر هش رسمی ارائه نکرده، هش محلی فقط تغییر یا خرابی بعدی را تشخیص می‌دهد و اصالت ناشر را اثبات نمی‌کند.

## Workflowها

| Workflow | کاربرد | نکته |
|---|---|---|
| Image Generate | تولید تصویر با متن | از مدل محلی انتخاب‌شده استفاده می‌کند. |
| Image Edit | تغییر تصویر بر اساس دستور | میزان شباهت به مدل، تنظیمات، متن و کیفیت ورودی وابسته است. |
| Enhance / Upscale | بازسازی تکسچر و افزایش ابعاد | Balanced / Strong / Maximum قدرت بازسازی متفاوتی دارند. |
| Close-up / Smart Zoom | پیدا کردن و برش سوژه یا استفاده از نقطهٔ فوکوس دستی | مکان‌یابی معنایی ممکن است خطا کند؛ نتیجهٔ مبهم را بررسی کنید. |
| Square 1:1 | گسترش عکس غیرمربع به قاب مربع | ترکیب مرزها احتمال خط را کاهش می‌دهد اما حذف همهٔ آرتیفکت‌ها تضمین نیست. |

## پیش‌نیازها

### اجرای سورس

- ویندوز ۱۰ یا ۱۱ نسخهٔ ۶۴ بیتی.
- CPython نسخهٔ ۶۴ بیتی 3.11، 3.12 یا 3.13 و Python Launcher (`py`).
- درایور سازگار با Backend انتخاب‌شده؛ GPU سازگار با NVIDIA/CUDA برای Runtime پیکربندی‌شده توصیه می‌شود.
- فضای دیسک کافی برای برنامه، Runtime، وزن‌های مدل، Cache و تصاویر خروجی. وزن‌های مدل داخل ZIP سورس نیستند.

### نسخهٔ نصب‌شده

نصب‌کننده فقط برنامهٔ بسته‌بندی‌شده، فایل‌های رابط و برندینگ، کتابخانه‌های لازم Python و اطلاعیه‌های مجوز را دارد؛ برای کم‌حجم ماندن، موتور بومی `stable-diffusion.cpp`، Runtime جداگانهٔ CUDA 12، Runtimeهای upscaler و وزن‌های مدل داخل آن نیستند. Runtime و وزن‌های مدل upscaler هنگام انتخاب/استفاده، مرحله‌ای دانلود و اعتبارسنجی می‌شوند. پس از نصب، در **Model Catalog** اجزای مدل را انتخاب و دانلود کنید؛ رابط دانلود پیشرفت را نشان می‌دهد و فایل‌ها را اعتبارسنجی می‌کند. سپس با **Load Selected Models**، اگر موتور موجود نباشد، برنامه آرشیو موتور پین‌شده (۳۳۸ مگابایت) و Runtime جداگانهٔ CUDA را دانلود، هش SHA-256 و محتوای آرشیو را بررسی و در `data/` استخراج می‌کند. دانلود اولیه به اینترنت نیاز دارد؛ پس از نصب همهٔ اجزای لازم، inference به‌صورت محلی انجام می‌شود و می‌تواند آفلاین باشد. حالت GPU-only مستلزم آن است که اجزای inference و بافرهای کاری در VRAM موجود جا شوند؛ اگر حافظه کافی نباشد، برنامه به‌جای انتقال مخفی به CPU خطای ظرفیت می‌دهد.

## اجرای مستقیم سورس برنامه

این روش برای توسعه‌دهندگانی است که می‌خواهند برنامه را از روی کد اجرا کنند. برای استفادهٔ عادی، نصب‌کنندهٔ ویندوز پیشنهاد می‌شود.

1. Python نسخهٔ ۶۴ بیتی 3.11 تا 3.13 را از منبع رسمی نصب کنید.
2. در ریشهٔ مخزن وابستگی‌ها را نصب کنید: `python -m pip install -r requirements.txt`.
3. برنامه را با دستور `python pai_ai_image_studio.py` اجرا کنید.
4. در **Model Catalog**، مؤلفه‌های لازم diffusion، text/vision encoder و VAE را انتخاب یا دانلود کنید؛ پیش از توزیع مجدد وزن‌ها، مجوز مدل را بررسی کنید.
5. در **Model Catalog → Ultimate** مدل upscaler و تنظیمات بازسازی tile را انتخاب کنید.

## ساخت نصب‌کنندهٔ ویندوز

ساخت فایل EXE نصب‌کننده باید روی ویندوز x64 انجام شود. PyInstaller ابزار cross-compiler نیست؛ بنابراین برنامهٔ ویندوزی باید در محیط ویندوز بسته‌بندی شود. برای توضیح رسمی به [راهنمای PyInstaller](https://pyinstaller.org/en/stable/) مراجعه کنید.

1. Python نسخهٔ ۶۴ بیتی 3.11، 3.12 یا 3.13 را نصب کنید.
2. Inno Setup 6 را از [صفحهٔ دانلود رسمی](https://jrsoftware.org/isdl.php) نصب کنید.
3. از ریشهٔ مخزن `Build_Windows_Installer.bat` را اجرا کنید.
4. وابستگی‌های ساخت را نصب می‌کند، نحو کدهای Python را بررسی می‌کند، برنامه را با PyInstaller در پوشهٔ تمیز `dist/` بسته‌بندی می‌کند و فایل نصب را می‌سازد.
5. فایل نهایی در پوشهٔ `dist-installer/` ریشهٔ مخزن ذخیره می‌شود: `PAI-AI-Image-Studio-Setup-<VERSION>.exe`؛ برای مقدار فعلی VERSION، نام فایل `PAI-AI-Image-Studio-Setup-1.0.0-beta.2.exe` است. آن را به پوشهٔ انتشار، فضای ابری یا بخش GitHub Releases کپی کنید. این پوشه‌های خروجی در Git نادیده گرفته می‌شوند؛ **فایل EXE، مدل‌ها و Runtime را به مخزن commit نکنید**.

موتور بومی، Runtime CUDA و وزن‌های مدل عمداً داخل نصب‌کننده نیستند و بعد از نصب دانلود می‌شوند. برای آماده‌سازی انتشار جدید، ابتدا `VERSION` را به‌روزرسانی کنید، نصب‌کننده را روی Windows x64 طبق مراحل بالا بسازید و فایل EXE را همراه ZIP سورس گزیده و فایل SHA-256 در GitHub Releases قرار دهید. تگ انتشار موجود را بازنویسی یا force-push نکنید.

## داده‌ها، حریم خصوصی و ایمنی

- Prompt و تصویر برای inference توسط Runtime انتخاب‌شده به‌صورت محلی پردازش می‌شوند؛ در مسیر پیش‌فرض، API میزبانی‌شده‌ای برای تولید تصویر استفاده نمی‌شود.
- دانلود Runtime و مدل‌ها ممکن است به شبکه دسترسی داشته باشد. فایل‌ها و مجوز منبع را بررسی کنید.
- خروجی عیب‌یابی فقط با درخواست کاربر ذخیره می‌شود، اما ممکن است مسیرها یا جزئیات محیط در آن وجود داشته باشد؛ پیش از اشتراک‌گذاری بازبینی کنید.
- تصاویر شخصی، مدل‌ها، Runtime، Token، تنظیمات، لاگ‌ها و پوشهٔ `.build-cache/` را به مخزن اضافه نکنید.
- GPU-only سیاست سخت‌گیرانهٔ محل اجرای مدل است. اگر وزن‌ها و فضای کاری در VRAM جا نشوند، عملیات ممکن است خطای ظرفیت بدهد. رابط، فایل‌ها و هماهنگی پردازش‌ها همچنان از CPU استفاده می‌کنند.

## عیب‌یابی

- **مدل در VRAM جا نمی‌شود:** کوانتایزیشن سازگار کوچک‌تر یا Auto/Low VRAM را امتحان کنید؛ GPU-only در نبود حافظه کافی عمداً ممکن است متوقف شود.
- **خروجی نهایی Real-ESRGAN موزاییکی است:** مطابقت فایل‌های مدل با نام مدل NCNN را بررسی کنید و `data/cache/engine/realesrgan.log` را ببینید. پیش‌نمایش حین Tile با فایل نهایی دو مورد تشخیصی جدا هستند.
- **بازیابی دیتیل ضعیف است:** ابتدا Balanced و سپس Strong را امتحان کنید. Maximum ممکن است تکسچر تخمینی بسازد یا جزئیات را تغییر دهد.
- **Close-up سوژه را پیدا نمی‌کند:** متن هدف را دقیق‌تر کنید یا نقطهٔ فوکوس دستی بگذارید.
- **فایل مدل پذیرفته نمی‌شود:** کامل‌بودن دانلود و نقش انتخاب‌شده را بررسی کنید؛ پسوند فایل به‌تنهایی سازگاری را ثابت نمی‌کند.

## وضعیت انتشار

نسخهٔ `1.0.0-beta.2` یک نسخهٔ آزمایشی است. تست خودکار و کامپایل در CI اجرا می‌شوند. کیفیت واقعی inference روی GPU، سازگاری درایورهای مختلف ویندوز، رفتار ارتقا/حذف نصب و فایل EXE کامپایل‌شده باید قبل از ادعای آماده‌بودن برای محیط تولید روی سخت‌افزار ویندوز آزمایش شوند.
